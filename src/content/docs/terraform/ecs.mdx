## What this example does

This example provisions:

- An S3 bucket (versioning + SSE-S3 enabled)
- An S3 Files file system and mount targets in each provided subnet
- IAM roles (file system role + ECS compute role used as both task and execution role)
- Security groups (compute → mount target on NFS port 2049), plus DNS and HTTPS egress for Logs/ECR
- A CloudWatch log group for the ECS task
- An ECS task definition with native `volume.s3files_volume_configuration`
- An ECS service running one Fargate task on the existing cluster

<Aside type="note">
  For the **EC2 launch type**, see [ECS on EC2](/s3-files-workloads/terraform/ecs-ec2/) — that example
  creates a cluster and container instance with an agent new enough for
  `ecs.capability.storage.s3-files`.
</Aside>

<Aside type="note">
  The example runs the service on the **existing** Fargate cluster you pass as
  `ecs_cluster_name`—it does not create a cluster. The cluster must be in the same region as
  `aws_region` (default `ap-southeast-6`).
</Aside>

<Aside type="note">
  Private subnets with `assign_public_ip = false` need a **NAT gateway** (or VPC endpoints for
  CloudWatch Logs and ECR) so the task ENI can reach AWS APIs on HTTPS.
</Aside>

<Steps>

1. **Confirm prerequisites.**

   | Requirement  | Minimum version                                           |
   | ------------ | --------------------------------------------------------- |
   | Terraform    | 1.5                                                       |
   | AWS provider | 6.41 (`s3files_volume_configuration` on task definitions) |
   | AWS CLI      | 2.34.26 (for log tail / optional verification)            |

   You also need an **existing ECS cluster** to deploy into. Confirm it exists:

   ```bash frame="terminal"
   aws ecs describe-clusters \
     --clusters <your-cluster-name> \
     --region ap-southeast-6 \
     --query 'clusters[0].status' \
     --output text
   ```

   Expected output: `ACTIVE`

2. **Clone the example.**

   ```bash frame="terminal"
   git clone https://github.com/jajera/terraform-aws-s3-files.git
   cd terraform-aws-s3-files/examples/ecs
   ```

   <FileTree>
     - examples/ecs/ - main.tf - terraform.tfvars.example - terraform.tfvars _(you create this)_
   </FileTree>

3. **Create `terraform.tfvars`.**

   ```bash frame="terminal"
   cp terraform.tfvars.example terraform.tfvars
   ```

   Edit `terraform.tfvars`:

   ```hcl
   vpc_id           = "vpc-0123456789abcdef0"
   subnet_ids       = ["subnet-aaaaaaaaaaaaaaaaa", "subnet-bbbbbbbbbbbbbbbbb"]
   ecs_cluster_name = "my-cluster"

   # Optional overrides (defaults shown):
   # aws_region           = "ap-southeast-6"
   # container_image      = "public.ecr.aws/amazonlinux/amazonlinux:2023"
   # log_retention_days   = 7
   # bucket_name          = null   # auto-generated: s3files-demo-<random>
   # bucket_force_destroy = true
   ```

   <div class="wide-table-wrap">

   | Variable               | Default                                               | Required | Description                                      |
   | ---------------------- | ----------------------------------------------------- | -------- | ------------------------------------------------ |
   | `vpc_id`               | —                                                     | yes      | VPC for mount targets and ECS tasks              |
   | `subnet_ids`           | —                                                     | yes      | Subnets for mount targets and Fargate task ENIs  |
   | `ecs_cluster_name`     | —                                                     | yes      | Name of an existing ECS cluster                  |
   | `aws_region`           | `ap-southeast-6`                                      | no       | AWS region (must match the cluster)              |
   | `container_image`      | `public.ecr.aws/amazonlinux/amazonlinux:2023`         | no       | Container image for the demo task                |
   | `log_retention_days`   | `7`                                                   | no       | CloudWatch log retention period in days          |
   | `bucket_name`          | auto-generated                                        | no       | Leave `null` to use `s3files-demo-<random>`      |
   | `bucket_force_destroy` | `true`                                                | no       | Allow destroy even when bucket contains objects  |

   </div>

4. **Initialise and apply.**

   ```bash frame="terminal"
   terraform init
   terraform plan
   terraform apply
   ```

   When apply finishes, note the outputs:

   ```bash frame="terminal"
   terraform output
   ```

   Key outputs:

   | Output                   | Description                                     |
   | ------------------------ | ----------------------------------------------- |
   | `ecs_cluster_name`       | Existing cluster name (from `ecs_cluster_name`) |
   | `ecs_service_name`       | ECS service name                                |
   | `task_definition_family` | ECS task definition family name                 |
   | `log_group`              | CloudWatch log group (`/ecs/<prefix>-s3files`)  |
   | `file_system_id`         | S3 Files file system ID                         |
   | `bucket_name`            | Backing S3 bucket name                          |

5. **Confirm the ECS service is running.**

   ```bash frame="terminal"
   aws ecs describe-services \
     --cluster "$(terraform output -raw ecs_cluster_name)" \
     --services "$(terraform output -raw ecs_service_name)" \
     --region ap-southeast-6 \
     --query 'services[0].{status:status,running:runningCount,desired:desiredCount}'
   ```

   Wait until `runningCount` equals `desiredCount` (1). This can take 2–3 minutes while the mount target becomes available and the container starts.

   <Aside type="note">
     If the task stops with `STOPPED` reason mentioning the file system, confirm that the mount
     targets are `available`:

     ```bash frame="terminal"
     aws s3files list-mount-targets \
       --file-system-id "$(terraform output -raw file_system_id)" \
       --region ap-southeast-6
     ```
   </Aside>

6. **Verify via CloudWatch Logs.**

   ```bash frame="terminal"
   aws logs tail \
     "$(terraform output -raw log_group)" \
     --follow \
     --region ap-southeast-6
   ```

   Expected output includes:

   ```text
   ====S3Files-df====
   Filesystem      Size  Used Avail Use% Mounted on
   127.0.0.1:/     8.0E     0  8.0E   0% /mnt/s3files
   ====listing====
   total 12
   drwxr-xr-x. 3 root root 10240 ... .
   drwxr-xr-x. 1 root root    21 ... ..
   drwx------. 2 root root 10240 ... .s3files-lost+found-fs-...
   -rw-r--r--. 1 root root    41 ... ecs-s3files-demo.txt
   ====read-back====
   written-at-2026-09-19T19:00:07Z-fargate-demo
   ====done====
   ```

   Press `Ctrl+C` to stop tailing.

7. **Tear down.**

   ```bash frame="terminal"
   terraform destroy
   ```

   <Aside type="caution">
     `terraform destroy` does **not** de-register ECS task definitions (AWS does not support
     deletion via API). The task definition family remains in your account in `INACTIVE` state
     after destroy.
   </Aside>

   <Aside type="note">
     If destroy fails deleting the file system with `ConflictException` / *data pending export
     to S3*, the AWS API supports `forceDelete=true`, but the Terraform
     `aws_s3files_file_system` resource does **not** expose that yet (tracked in
     [hashicorp/terraform-provider-aws#47588](https://github.com/hashicorp/terraform-provider-aws/issues/47588)).
     For a throwaway demo, force-delete via the CLI, then re-run destroy:

     ```bash frame="terminal"
     aws s3files delete-file-system \
       --file-system-id "$(terraform output -raw file_system_id)" \
       --force-delete \
       --region ap-southeast-6

     terraform destroy
     ```

     If Terraform still thinks the file system exists after the CLI delete:
     `terraform state rm 'module.s3_files.module.filesystem.aws_s3files_file_system.this'`.
   </Aside>

</Steps>
